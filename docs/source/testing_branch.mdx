## 1. Convert ROS Bag to LeRobot Dataset

### Available Converters

The testing branch provides two conversion scripts with different capabilities:

#### Standard Converter

Located at `dev/data_processing/conversion/rosbag_to_lerobot_rosbag2.py`

**Features:**
- Supports multiple input modes: `vision_only`, `vision_pos`, `vision_pos_vel`
- Supports multiple output modes: `pos_only`, `pos_vel`
- Configurable FPS and image preprocessing
- Automatic trimming of unmoving segments

**Usage:**
```bash
cd dev/data_processing/conversion

python rosbag_to_lerobot_rosbag2.py \
    /path/to/rosbags \
    --output-dir /path/to/output/dataset \
    --dataset-name "my_robot_dataset" \
    --fps 20 \
    --task "Robot manipulation task description" \
    --tolerance 1.0 \
    --input-mode vision_pos \
    --output-mode pos_vel
```

#### Cropped & Trimmed Converter

Located at `dev/data_processing/conversion/rosbag_to_lerobot_cropped_trimmed.py`

**Features:**
- Custom image preprocessing (crop, rotate, resize)
- Top view: Crop → Rotate 90° CW → Resize to 224×178
- Left arm: Resize to 224×178
- Precise episode trimming

**Usage:**
```bash
python rosbag_to_lerobot_cropped_trimmed.py \
    /path/to/rosbags \
    --output-dir /path/to/output/dataset \
    --dataset-name "cropped_dataset" \
    --fps 20 \
    --trim-start 30 \
    --trim-end 30
```

### Input/Output Modes

The converter supports flexible input and output configurations:

| Input Mode | Description | Observation Dimension |
|------------|-------------|----------------------|
| `vision_only` | Only camera images | Images only |
| `vision_pos` | Images + joint positions | Images + 6D |
| `vision_pos_vel` | Images + positions + velocities | Images + 12D |

| Output Mode | Description | Action Dimension |
|-------------|-------------|-----------------|
| `pos_only` | Joint positions only | 6D |
| `pos_vel` | Positions + velocities | 12D |

### Expected ROS Topics

The converter expects these ROS2 topics:
- `/sync/emily01/left_arm/color/image_raw/compressed` - Left arm camera
- `/sync/emily01/head/color/image_raw/compressed` - Head/top view camera
- `/sync/joint_states` - Joint state information

### Verify Dataset

After conversion, inspect the dataset:

```bash

# Or use the provided script

```

## 2. Train the Model

### Standard Training (Absolute Actions)

Train with standard absolute action representation:

```bash
python lerobot/scripts/train.py \
    --config-path /path/to/config.json \
    --output-dir /path/to/output \
    --dataset-repo-id /path/to/local/dataset
```

**Using the example script:**
```bash
python examples/3_train_policy.py
```

### Relative Action Training (Recommended)

Train with relative action representation for better generalization:

```bash
python lerobot/scripts/train_with_relative_actions.py \
    --config_path /path/to/config.json \
    --output_dir /path/to/output \
    --use_relative_actions \
    --arm_dim 6 \
    --obs_horizon 2
```

**Key Parameters:**
- `--use_relative_actions`: Enable relative action mode
- `--arm_dim 6`: Number of arm joints (excluding gripper)
- `--obs_horizon 2`: Number of observation frames to use
- `--relative_stats_path`: Optional pre-computed statistics

### Compute Relative Action Statistics

Pre-compute normalization statistics for better training:

```bash
python lerobot/scripts/compute_relative_action_stats.py \
    --dataset-path /path/to/dataset \
    --arm-dim 6 \
    --obs-horizon 2 \
    --output-path ./relative_stats.json
```

### Training Outputs

Training outputs are saved in the output directory:
- `checkpoints/` - Model checkpoints (best, last, periodic)
- `logs/` - Training logs and metrics
- `config.json` - Full configuration used for training

## 3. Convert Model to ONNX

After training, convert the PyTorch model to ONNX for optimized inference (3-10x faster).

### For Absolute Action Models

```bash
cd dev/inference/testing_abs

python convert_to_onnx.py \
    --checkpoint /path/to/checkpoint \
    --output-dir ./onnx_models \
    --opset-version 17
```

### For Relative Action Models

```bash
cd dev/inference/testing_rel

python convert_to_onnx_rel.py \
    --checkpoint /path/to/checkpoint \
    --output-dir ./onnx_models \
    --use-relative-actions \
    --arm-dim 6 \
    --opset-version 17
```

### ONNX Export Outputs

The conversion creates:
- `vision_encoder.onnx` - RGB encoder network
- `noise_pred_net.onnx` - Diffusion UNet
- `config.json` - Model configuration
- `normalization_stats.json` - Data normalization statistics

### Verify ONNX Models

Test the ONNX models before deployment:

```bash
python -c "import onnxruntime as ort; \
    session = ort.InferenceSession('./onnx_models/vision_encoder.onnx'); \
    print('Model loaded successfully!')"
```


### ROS2 Topics

**Subscribed Topics:**
- `/sync/emily01/left_arm/color/image_raw/compressed` - Left arm camera (CompressedImage)
- `/sync/emily01/head/color/image_raw/compressed` - Top view camera (CompressedImage)
- `/sync/joint_states` - Current joint states (JointState, if needed by model)

**Published Topics:**
- `/left_arm/joint_trajectory` - Predicted joint commands (JointTrajectory)

### Inference Modes

**Continuous Mode (Recommended):**
- Runs at fixed frequency (e.g., 20 Hz)
- Predictable timing
- Best for closed-loop control

**Triggered Mode:**
- Runs on new sensor data
- Variable frequency
- Uses latest data

## Troubleshooting

### Common Issues

**Issue: CUDA Out of Memory**
```bash
# Solution 1: Use CPU
python inference_node.py --device cpu

# Solution 2: Reduce frequency
python inference_node.py --frequency 10.0
```

**Issue: Image Size Mismatch**

Verify preprocessing matches training pipeline. Check crop/resize parameters in the conversion script.

**Issue: Robot Not Moving**

1. Verify topic names match your robot configuration
2. Check robot controller is subscribed to action topic
3. Verify model outputs non-zero actions
4. Check sensor data is publishing

**Issue: Inference Too Slow**

1. Use ONNX instead of PyTorch
2. Reduce inference frequency
3. Check GPU utilization with `nvidia-smi`
4. Consider using TensorRT backend

## Architecture Overview

### Image Preprocessing Pipeline

The testing branch implements a sophisticated image preprocessing pipeline that matches the training process:

1. **Top View (Head Camera)**:
   - Original: 640×480 RGB
   - Crop to bounding box: (x=260, y=135, w=178, h=224)
   - Rotate 90° clockwise
   - Final size: 224×178

2. **Left Arm Camera**:
   - Original: 640×480 RGB
   - Resize to 224×178
   - Final size: 224×178

3. **Normalization**:
   - Convert to [0, 1] range
   - Transform to CHW format (3×224×178)

### Action Processing

**Absolute Actions:**
```
Model Output → Denormalize (using stats) → Joint Commands
```

**Relative Actions:**
```
Model Output (Δ) → Denormalize → Add to Current State → Joint Commands
```
